# 流程：记忆园艺（garden-memory）

**默认只报告，不修改任何文件。** 用户对具体条目确认后才动手，且只作用于记忆目录。

> `<引擎>` 指本 skill 目录下的 `engine/mem.py`。

## 1. 链接健康

```
py -3 <引擎> check
```

脚本会列三类问题：

- **红链**：指向不存在笔记的双链，并给出最接近的现有笔记建议
- **跨目录链接**：记忆笔记 → 其他目录（对话中明确提及的可保留）
- **可疑别名**：别名与目标名差异过大，通常是 Obsidian 自动补全误链

## 2. 格式问题

```
py -3 <引擎> validate
```

检查 frontmatter 缺字段、tags 数量越界、文件名非法、UTF-8 BOM、高频泛词标题。

## 3. 内容层面的体检

在记忆目录里人工判断，脚本替代不了：

- **薄笔记**：正文 < 10 行且主题与别的笔记重叠 → 建议合并
- **同义 tags**：`mcp` vs `MCP`、`llm` vs `LLM` → 建议统一
- **超载域笔记**：某个子主题小节超过 ~5 个 → 建议拆分
- **长期零召回**：`recall_count: 0` 且 `created` 超过 14 天 → 建议归档或合并

零召回的笔记先确认它是不是真的检索不到，再下结论：

```
py -3 <引擎> find <它应该被哪些词召回>
```

能召回到却从未被用过，问题在「没人问过这类问题」，不在笔记本身。

## 4. 输出清单

按「问题类型 / 涉及笔记 / 建议动作」三列输出。

**不自动执行任何修复**，哪怕看起来很明显。

## 5. 逐项确认后修复

用户对具体条目确认后，才执行对应修复，且仅作用于记忆目录。

修完再跑一次 `check` 和 `validate` 确认没有引入新的红链或格式问题。
