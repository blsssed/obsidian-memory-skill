# 流程：图谱混合召回（recall）

任务可能受益于历史经验时加载本文件。

> `<引擎>` 指本 skill 目录下的 `engine/mem.py`。

## 1. 提炼关键词

从当前任务中提炼 2~5 个检索关键词：技术名词、报错信息、工具名、项目名。

用户手动给出的关键词**优先**，不要用自己想的替换。

## 2. 跑召回

```
py -3 <引擎> recall <关键词...> --record
```

`--record` 会顺带给本次输出的种子笔记 `recall_count +1`，供园艺识别「从未被召回」的死笔记。

脚本内部依次完成：同义词扩词 → 标签/标题/正文三通道种子计分 → 图谱一跳扩展（跳数衰减 × 边类型系数）→ 总分排序 → 字数预算内输出。

读输出时要认这几种标记：

| 标记 | 含义 |
|---|---|
| `★` | 种子笔记，给的是正文（单篇有截断） |
| `☆` | 邻居笔记，只有标题 + 首行 + 到达边 |
| `←solved_by` | 这篇是某个问题的解法，优先看 |
| `←related` / `←part_of` | 泛相关 |
| `⚠️已过时` | 经 `supersedes` / `superseded_by` 到达，结论可能已被推翻 |

## 3. 深读邻居

邻居只给了首行，不够判断相关性。看起来相关的，读它的全文再决定要不要用。

## 4. 注入上下文

把与当前任务相关的要点（结论、命令、坑）注入上下文，并在回答中注明来自哪篇笔记。

经 `superseded_by` 到达的笔记要明确标注「已过时」，谨慎采用——它的存在本身就说明有更新结论。

## 5. 无命中时

同义词扩展后仍无命中，直接告知用户「没有找到相关历史记忆」，正常继续任务。

**不要为了凑结果放宽关键词或降低阈值。** 空召回是正常状态，比塞进无关笔记更有价值。
