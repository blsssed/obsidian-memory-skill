# 合并规则（merge-rules）

「保存记忆」流程第 3 步使用。对每条提取出的知识，按以下顺序判定，命中即停。

## 路径 A：新建

**条件**（需同时满足）：
- 检索后 `AI记忆/` 中没有同主题笔记
- 该知识自成主题（不是某篇已有笔记的自然延伸）

**操作**：按 note-template.md 新建笔记，正文含 2~5 条指向真实笔记的双链（vault 内相关笔记不足 2 篇时按实际数量）。

**域级合并**：一次提取出**多条同域薄知识**（每条各自撑不起一篇独立笔记，如"temp=0 实践值" + "tenacity 坑" + "SDK 自带重试"）时，SHALL 合并写入一篇域级经验笔记（命名如 `LLM API工程经验.md`），每条知识一个 `### 日期 · 子主题` 小节——**禁止每条各建一个文件**。判定"撑不起"：单条内容在笔记中不足 3 行且预期不会独立生长。

## 路径 B：追加

**条件**：
- `AI记忆/` 中已有笔记的主题与该知识相同（判定依据：标题相似 / tags 重合 / 检索命中同一关键词簇）
- 新知识**不与**该笔记已有结论矛盾

**操作**：
- 追加到 `## 详情` 末尾的 `### YYYY-MM-DD 补充` 小节
- 更新 `updated` 字段
- 若引用了新的相关笔记，补充双链

## 路径 C：标注取代

**条件**：
- 已有笔记中的某个结论，被本次对话的新认知**明确推翻**（不是补充，是矛盾）

**操作**：
- 旧笔记：旧结论加 `> ⚠️ 已被修正（见 [[新笔记]]）` 标注，不删除原文
- 新结论：若量级足够独立成篇则新建笔记并在 frontmatter 写 `supersedes: "[[旧笔记]]"`；若只是旧笔记内一节的修正，则直接在旧笔记的补充小节里写明，不新建
- 旧笔记 frontmatter 补 `superseded_by` 指向新笔记（如有）

## 判定边界

- 拿不准"同主题"还是"新主题"时：看两个知识是否会共享同一批双链邻居——会则同主题（追加），不会则新建
- 多条知识指向同一篇已有笔记时，合并为一次追加写入（一次 Edit），不要多次小改
- 用户 vault 中 `AI记忆/` 以外的笔记**只读**：可以双链它们，但永不修改它们——若旧结论在 vault 其他目录的笔记里，新建一篇记忆笔记说明修正并双链过去

## 域笔记分裂信号

域级笔记中某个子主题积累超过 ~5 个小节时，在汇报中提示用户"该子主题已足够独立，建议拆分"。拆分本身由「整理记忆」流程在用户确认后执行，不自动操作。
