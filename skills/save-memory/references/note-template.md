# 笔记模板（note-template）

「保存记忆」流程第 4 步使用。所有写入 `AI记忆/` 的文件必须遵循本模板。

## 目录结构

```
AI记忆/
├── <主题名>.md 或 <域>工程经验.md    ← 经验笔记（记录"经验与决策"）
└── snippets/<描述性名称>.md          ← 素材文件（纯文本块，无解释）
```

## 文件名规则

格式：`<主题名>.md`（**不带日期前缀**——主题笔记应当随时间生长，同主题追加而不是堆日期文件）

- 主题笔记：一句话名词短语，如 `MCP架构认知.md`、`Windows路径坑.md`
- 域级笔记：一次提取的多条同域薄知识合并时用，命名如 `LLM API工程经验.md`（见 merge-rules.md）
- 素材文件：描述性名称，如 `tenacity重试模板.md`、`密码校验正则.md`
- 清洗 Windows 非法字符：`\ / : * ? " < > |` → 删除或替换为 `-`
- 长度 ≤ 50 字符；避免纯数字开头
- **标题避开 vault 高频泛词**（如"笔记""skill""未命名"）——降低用户日后在 Obsidian 中输入这些词时被自动补全误链的概率
- 编码一律 UTF-8（无 BOM）

## 经验笔记 Frontmatter 模板

```yaml
---
tags: [2~5 个主题词, 小写, 中英不限]
source: claude-code
created: YYYY-MM-DD
updated: YYYY-MM-DD
recall_count: 0                     # 可选：被 /recall 命中为种子的次数，由 graph.py record 维护
related: ["[[相关笔记名]]"]        # 可选，泛相关
solved_by: "[[解法笔记名]]"        # 可选，本笔记是问题时用
supersedes: "[[被取代的旧笔记]]"   # 可选，本笔记取代了谁
part_of: "[[所属主题MOC]]"        # 可选
---
```

- `created` 首次写入时设置，此后不改；`updated` 每次追加/修改时更新
- 类型化边仅在语义真实成立时添加，**宁缺毋滥**；值必须是真实存在的笔记名（写入前用 Glob 验证）
- 用户显式要求保存白名单外内容时，`source` 改为 `user-requested`

## 素材文件模板（snippets/）

```yaml
---
type: snippet
tags: [2~4 个技术词]
source: claude-code
created: YYYY-MM-DD
---
```

正文**只放原始文本块本身，不加任何解释**。经验、适用条件、坑一律写在引用它的经验笔记里。素材文件可以被多篇经验笔记 `[[双链]]` 引用。

## 经验笔记正文模板（新建时）

```markdown
# <主题名>

## 一句话结论
<这条知识最精炼的表述，先给结论>

## 详情
<展开：背景 / 过程 / 证据。踩坑类必须包含「现象 → 根因 → 解法」三段>
<大段代码/配置不内联，替换为 [[素材名]] 链接 + 一行说明>

## 相关
- 详见 [[相关笔记]]（<一句话说明关系>）

---
*来源：Claude Code 对话总结 · 首次记录 YYYY-MM-DD*
```

## 追加时（已有笔记）

- 新知识追加到 `## 详情` 末尾，用 `### YYYY-MM-DD 补充` 小节隔开（小节头即块级元数据，承载来源时间）
- 若新内容修正了正文中的旧结论：旧结论保留但标注 `> ⚠️ 已被修正（见下方 YYYY-MM-DD 补充）`
- 同步更新 frontmatter 的 `updated` 和（如需）`tags`
- **不重写已有正文**，只追加和标注
